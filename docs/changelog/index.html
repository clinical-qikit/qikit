    Changelog¶

    Unreleased¶

    Documentation¶

    • A documentation site at https://clinical-qikit.github.io/qikit/docs/: the guide, the methods, an API reference built from the docstrings, and this changelog. The guide pages are drawn from the README's sections, so the README stays the one copy. Each release tag publishes it; mkdocs build --strict runs in CI.

    1.4.5 (2026-11-19)¶

    Fixed¶

    • funnel() no longer stalls on proportions with a provider far below the center line. The shrunk-estimate interval inverts a beta distribution; when a provider's posterior had a shape near 0, each evaluation ran its continued fraction off the side where it converges, 100,000 terms at a time, and a funnel could take minutes. Each tail now comes from the fraction that converges at that point; values agree with the previous ones to 1e-11 and no snapshot moved.
    • A proportion funnel's upper limits stop at 1. When the providers spread wider than any beta distribution allows, the limits fall back to the published normal formula, whose upper contour could pass 1 (2.34 in one case); the lower contour was already stopped at 0.

    Tests¶

    • Property-based tests (tests/test_properties.py, Hypothesis): rules that hold for any input rather than one example, such as limits nesting around the center line, a change of units moving the I chart and keeping its signals, freeze= ignoring later points, each part= being its own chart, a funnel ignoring the order of providers, excluding a provider being the same as leaving it out, and an incomplete row being dropped and counted. They found both fixes above.
    • CI runs on Python 3.14.

    1.4.4 (2026-11-17)¶

    Fixed¶

    • funnel(exclude=7) takes a single unit id, as qic(exclude=) does; it raised TypeError: 'int' object is not iterable. exclude=True now says it wants ids or a column name.
    • Without data=, a hover= entry named like a result column is refused. With hover={"numerator": [...]} the hover values silently replaced the numerator column in result.data; it now raises, as it already did with data=.
    • Without data=, unit= or label= as a string is refused. It was read as a sequence of letters (label="name" labelled four providers n, a, m, e); it now says to pass a sequence.

    Tests¶

    • tests/conformance_helpers.py is gone. The Python tests use qic() and funnel() directly; tests/fixture_adapter.py (311 lines, from 447) runs the shared fixtures in the TypeScript engine's vocabulary, and tests/test_fixture_adapter.py pins the parts of that vocabulary that are not simply new names.

    Excel add-in¶

    • A privacy and security page is published with the add-in (privacy.html beside the task pane) and set as the JSON manifest's privacy URL. It covers what is loaded and from where, what is read and written in the workbook, and how to review or pin a version.
    • A Content Security Policy on every published page: scripts only from the add-in's folder and Office.js's hosts, no eval, no frames, and network requests only to the add-in's folder and Office.js's. npm run build fails if a page lacks it.
    • Copy details on every error. Each panel's error message, and the crash screen, offer Copy details: the add-in and Excel versions, the panel, the message, the Office.js error code and the trace, ready to paste into an issue. Nothing is sent. Office.js error codes were previously dropped when the add-in reworded the message.
    • A public demo: latest/demo.html runs the task pane against a sample workbook in any browser.
    • Component tests: the four panels are tested end to end through the demo's mock workbook (jsdom and Testing Library), including errors and the crash screen.

    Fixed (Excel add-in)¶

    • The Bernoulli CUSUM panel picks the 0/1 column. With an ID column first, it used the IDs and failed with "Target must be between 0 and 1". It now starts on the first column of 0s and 1s, and a column with other values gets a message saying what the panel needs. Blank cells are skipped; they were counted as 0 (no event).
    • The task pane works in Excel. Since 1.4.2 the published task pane also loaded the browser demo's mock of Office.js, which replaced Excel's own: in Excel the pane showed the demo with made-up data and never read or wrote the workbook. The demo is now a separate page, demo.html, and npm run build fails if the task pane's scripts contain the mock. Opened in a browser, the task pane now says it runs in Excel and links to the demo.

    1.4.3 (2026-11-17)¶

    Excel add-in¶

    • An XML manifest is published beside the app package (manifest.xml in latest/ and each version folder), generated from manifest.template.xml and checked by Microsoft's validator in CI and before publishing. It is for installing without an administrator where Teams uploads are turned off: "Upload My Add-in" in Excel, or sideloading on Mac and Windows. docs/deployment.md describes each route and how to tell whether an organization has blocked it.
    • The SPC panel says what it found. Under the chart, a verdict and a sentence per finding ("A shift: 12 points in a row below the center line, Jan 2026 to Dec 2026.", points outside the limits by name, too few crossings), and the Python notes word for word when fewer than 12 points set the center line or fewer than 20 set the limits.
    • Try with sample data. The empty SPC panel offers a made-up, labelled two-year monthly series on a new sheet, so a new user sees a chart and a finding at once.
    • Help me choose. Up to two plain questions (a measurement or a count; which kind of denominator, or one value or an average) pick the chart, defaulting to a run chart when unsure. Choosing a P or U chart without its denominator now says which box to fill.
    • Settings are remembered per workbook (chart type, data grain, rules and limit options, include source data), saved in the workbook once you change one.

    Fixed (Excel add-in)¶

    • Dates in Excel are recognized as dates. Excel hands date cells to an add-in as serial numbers, so a real date column was read as numbers and could not set the x-axis or be grouped by month. Columns are now classified by their number format; date text is recognized only when it looks like a date ("Ward 3" and "3" no longer do). The reporting period follows the data's spacing, so daily data is no longer folded into months by default.
    • Rows that cannot be used are listed, not silently dropped, with the sheet row and the reason (no value, not a number, no date, no denominator, denominator 0).
    • A missing denominator is never read as zero. By date, a row with no denominator added its count but nothing to the total, inflating that period's rate; elsewhere one bad denominator dropped the whole denominator column.
    • Labels, notes and included source data stay with their points when rows are left out; they shifted by one for every skipped row. Live updates read formats too.

    1.4.2 (2026-11-17)¶

    Fixed¶

    • One-factor-at-a-time designs are analyzed as what they are. analyze() applied the factorial formula to design_type="one_factor", whose runs are not balanced, so every effect was wrong (in a three-factor example an effect of 4 came out as −7.75, with interactions that such a design cannot estimate). Each effect is now the mean with that factor high minus the mean of the baseline runs, which is the least-squares fit. Only main effects are reported, and ss and pct_contribution are NaN because the terms do not partition the total. The Excel engine has the same fix (shared fixture effects_one_factor) and writes those two cells blank.
    • plot("cube") draws two-factor experiments as a square with the mean response at each corner, where it showed "coming soon". One factor raises, naming chart="single_factor".
    • plot("line_effects") is in standard order, as its title says. It plotted the response in run order, which is a different chart once the design is randomized. Replicates follow in turn and center points come last; hover shows each run's number.

    Excel add-in¶

    • Installable without the repository. Each release tag publishes the task pane to GitHub Pages under vX.Y.Z/ and latest/, each with an app package (qikit-excel-addin.zip) for the Microsoft 365 admin center or Teams custom-app upload. docs/deployment.md is rewritten around those routes, self-hosting, and a privacy statement.
    • Production manifest. The unified manifest moves from the devPreview schema to 1.29, with a GUID, hosted URLs, the 192 px and outline app icons, an 80 px ribbon icon, a tooltip, and an ExcelApi 1.7 requirement (chart series and the series axis). It is generated from manifest.template.json; the committed manifest.json is the dev manifest ("QI Kit (dev)", its own id). CI builds the add-in and checks both manifests with Microsoft's validator and the published schema.
    • The task pane shows its version, which is the Python package's.

    Documentation¶

    • docs/snowflake.md named the 1.1.0 wheel in its PUT and IMPORTS lines; it now names the current one, and a test fails when the version moves on without it. The stored procedure and UDTF in that doc are now run by the tests, which check that the UDTF returns the columns its RETURNS TABLE clause declares. Faceted-funnel timings are added to the performance table.

    1.4.1 (2026-11-16)¶

    Fixed¶

    • The plot, app and dev extras now require plotly>=5.21. They declared 5.15, but the charts use trace zorder, which plotly added in 5.21; on an older plotly .plot() raised ValueError: Invalid property ... 'zorder'. The tables never needed plotly and are unaffected.
    • One-sided funnel p-values were reversed where the normal model stood in for the exact one (summary["p_value_method"] == "normal"). With worse="higher" or "lower" the provider furthest in the bad direction got the largest p-value, not the smallest, so signal="fdr" could miss it and p_value/q_value were wrong for every provider on that funnel. This arises only when the exact model is unavailable: a proportion funnel whose spread is wider than any beta distribution allows, or over-dispersed counts in the millions. Two-sided p-values (worse unset) and the limits themselves were always correct.
    • design(...).fill(...).plot("timeseries") raised a TypeError from an argument qic() no longer takes.
    • ExperimentDesign.to_json() wrote NaN, which is not JSON, for the unfilled Response column; it and to_dict() now give null/None.
    • Center points no longer shrink the effects of an experiment. analyze() divided each contrast by every run, center points included, so a 2×2 with an A effect of 13 reported 8.67 once two center points were added. Effects, sums of squares and pct_contribution now come from the factorial runs alone, which is the least-squares fit; designs without center points are unchanged. The Excel engine had the same formula and has the same fix, with a shared fixture (effects_center_points).
    • design(randomize="within_blocks") with center points mixed the replicates. The block length counted the center points, so blocks straddled replicates. Each replicate is now shuffled on its own and the center points stay at the end.

    1.4.0 (2026-11-11)¶

    Minimum denominators from a reliability target. Additive; no result changes.

    Added¶

    • result.min_denominator(reliability=0.7) on funnel() results: the denominator at which a provider's reliability reaches a target (one or several), in the units of n=, with its range from the 95% interval for τ, the number of providers at or above and below it (n_above, n_below), the volume they hold, and each row as a sentence (note). It agrees exactly with the reliability column. When the data show no spread between providers there is no floor, and the result says so.
    • funnel_rollup(data, units=[...], reliability=0.7, ...): the same table for each level of a hierarchy (physician, group, hospital), each fitted separately, for deciding the level at which small providers are rolled up.
    • summary["estimate_tau_ci"]: the profile-likelihood 95% interval for the spread the estimate columns use (estimate_tau). None when tau= is given.
    • skills/minimum-denominators/SKILL.md and a "Minimum denominator recipe" in AGENTS.md: what an agent asks (measure, level, peer group, use, period), calls and reports when asked for a minimum denominator or a rollup level.

    1.3.0 (2026-11-10)¶

    Messy input no longer becomes a silent wrong answer, and results gain a predictable, compact surface for pipelines and agents. Nothing is removed.

    Added¶

    • qikit.schema("qic" | "funnel"): every column result.data can hold, with its type, whether every call produces it, and its meaning. It is now the single source of the column lists.
    • result.to_table() on qic() and funnel() results: .data with every schema column, in schema order and with fixed types (nullable booleans and integers, strings as objects), empty where the call did not produce it; the facets= columns first and the hover= columns last. The shape a database table or a Snowpark RETURNS TABLE clause needs, whatever options the call used.
    • result.brief(digits=4, limit=25): what was found as a small JSON-safe dict: the verdict or counts, the notes, and only the flagged points (the most recent) or providers (outliers first, then by p-value). About 1 KB where to_json() is tens.
    • result.facet_summary(): the summary as a table, one row per facet, with the same columns faceted or not.
    • to_dict(digits=) and to_json(digits=): round every number to that many significant figures. Default unchanged.
    • Choices ignore case and surrounding spaces (measure="OE", signal=" FDR "), and a misspelt choice or keyword suggests the closest: measure must be one of ..., got 'proportions'. Did you mean 'proportion'?; qic() got an unexpected keyword argument 'charts'. Did you mean 'chart'?.
    • The signatures spell out the choices as Literal types (chart, method, measure, worse, signal, tau_method, benchmark, compare_to, agg_fun), so help(), editors and type checkers show them.
    • bchart(x, ..., data=) takes a column name, as paretochart() does. It now refuses values that are not 0/1 and a baseline= outside the cases, in place of a confusing error or a silent pass.
    • print() of a paretochart() or bchart() result says what was found.
    • qic() summary["notes"] and summary["provisional"]: sentences to show a reader (fewer than 12 baseline points, control limits from fewer than 20, points with no value, a frozen baseline), as funnel() already had; provisional is True under 12 baseline points. Faceted, the notes are prefixed by facet. print(result) shows them.
    • Column-name errors list the columns and suggest the closest, ignoring case, in qic(), funnel() and paretochart(): y='deaths' is not a column of data. Did you mean 'DEATHS'?. funnel()'s message changes from "must name a column of data".

    Fixed¶

    • funnel() read a missing value as zero. A provider whose y was missing was summed to 0 events and could be flagged a low outlier. A row missing y, n or unit is now left out of the sums and counted in the new summary["n_rows_dropped"], with a note; a provider with no complete row is listed with no value and is not tested. A missing denominator no longer raises "events but a zero denominator", and rows with a missing unit are no longer dropped unannounced.
    • qic() charted Python date objects in row order. Snowpark's to_pandas() returns a DATE column as datetime.date objects, which were treated as text and left unsorted, so limits and run rules were computed on shuffled time. They are now sorted like any other date, and .data["x"] keeps the date objects.
    • qic() turned text that is not a number into a gap. "x" or "n/a" in y, n or target now raises a ValueError showing the values; funnel() and bchart() give the same message in place of a raw numpy error. None, NaN, blank text, numeric text and Decimals are read as before.

    • A handful of points was called stable. print(qic(y=[5])) no longer says "the process looks stable".

    • to_json() raised on Python date values in x and Decimal unit ids, as Snowpark returns DATE and NUMBER columns. Dates serialize as ISO text, Decimals as numbers.

    • A faceted qic() summary lacked the top-level runs_signal.
    • qic()'s docstring did not document the special_cause column.

    Changed¶

    Every funnel() result is unchanged, bit for bit.

    • The pure maths moved out of funnel.py into core/: core/shrinkage.py (the prior, shrunk estimates, posterior intervals and P(worse), now one pass instead of two), core/benchmark.py (the achievable benchmark and minimum sufficient denominator), and the pooled center and fixed-center gap test into core/dispersion.py. The within_dispersion readers, which work on pandas rows, are in the new within.py. funnel.py goes from 1,790 lines to about 1,400, and its helpers take one fitted-model object instead of nine to eleven arguments.
    • Warnings are attributed to the caller's line wherever in the package they arise.
    • multiply= in qic() and tau= in funnel() share one number check; qic()'s message is now "multiply must be a number > 0".

    1.2.0 (2026-11-08)¶

    Added¶

    • compare_to= on funnel(): names which question the chart answers. "peers": the pooled center line and overdispersion=True (the default settings). "model": O/E against the risk model's expected, center=1.0 and overdispersion=False; measure="oe" only, and a proportion or rate is told to pass center=<target>, overdispersion=False. A center= or overdispersion= that contradicts it is an error naming the fix; agreeing values are allowed. summary["compare_to"] records "peers", "model" or "custom" on every call, and print(result) ends its first line with the question. Passing compare_to= adds a note saying which question the chart answers. funnel_sensitivity() forwards "peers" and rejects "model", whose runs would all be the same chart.
    • overdispersion= now defaults to None (meaning True unless compare_to="model"), so an agreeing value can be told from an unset one. Every existing call resolves as before.
    • A warning for a fixed center under the spread allowance: center= with overdispersion=True let τ̂ absorb any system-wide gap between the providers and the center, silently widening every limit (center=1.0 on a system running 10% above its risk model nearly quadrupled τ̂). When the gap is beyond chance (p < 0.001, a sandwich-variance t test) and widens the limits at the median volume by at least 10%, funnel() raises a UserWarning and adds a note with the gap, the widening and the fix. New summary keys center_gap, center_gap_p and tau_pooled. Skipped under a pre-specified tau=. Calibrated by scripts/simulate_center_gap.py: at most 0.4% false warnings in any cell; methods §4.2.1, §5.
    • README, the docstring, AGENTS.md (a new funnel decision recipe, with a canonical physician LOS vs Vizient expected call and scorecard-wide FDR), the provider-funnels skill and llms.txt now pair "against the risk model" with compare_to="model" rather than center=1.0 alone. The README's "identical when τ̂ = 0" now says it holds around the pooled center only.

    • Python only; the Excel add-in does not draw funnels.

    • measure="mean" on funnel(): compares providers on a per-case amount, such as EHR minutes per discharge or cost per case, in the amount's own units. Pass one row per case (y= the amount; n= may be omitted), or SQL totals (y=SUM, n=COUNT(*), sum_sq=SUM(y*y)). The center line is the pooled mean, and cases are on the x axis. It is the quasi-Poisson model with within_dispersion always estimated, so every option applies: worse=, signal="fdr", tau_method, max_case_y=, benchmark="eb", facets= and multiply=. It gives exactly the result of the earlier workaround (each case ÷ the pooled mean as O/E, then multiply=), without the rescaling. Methods §4.19.

    • summary["case_sd"]: the SD of a single case, in y's units.
    • Amounts must be ≥ 0. A scalar within_dispersion, cases= and max_case_n= are refused under "mean", because n already is the case count and a single case's denominator is 1.
    • n= is now optional in the signature; every other measure still requires it.
    • The benchmark= docs now say which option suits which measure: "abc" for proportions, "eb" for "oe", "rate" and "mean".
    • Python only; the Excel add-in does not draw funnels.
    • Shrunk estimates with a range, and a caterpillar plot: new columns eb_low and eb_high, an equal-tailed interval for each provider's true value from its exact posterior (gamma on counts, beta on proportions, on effective counts), with interval= (default 0.95), and estimate_flag: "worse", "better" or "no different" ("higher"/"lower" without worse=) as the interval lies against the reference. estimate_flag answers "clearly worse than the reference?", where signal answers "unusual?"; signal is unchanged. No interval and a note when there is no measurable spread. result.plot(kind="caterpillar") draws them: providers sorted by eb_rate, intervals colored by estimate_flag, raw values faint, the reference dotted, small multiples per facet, and top=/bottom= for long lists. New summary keys reference and estimate_tau. Methods §4.14, §5.
    • The estimate columns' prior now uses the ML τ̂ (or tau=) whatever tau_method the limits use, so eb_rate, eb_excess, reliability, prob_worse and benchmark="eb" values change. The published estimator understates τ: under it 95% intervals covered 49–89% of true values, under ML 91–95%. Limits, p-values, q-values and signal are unchanged. An ML τ̂ that would leave every provider's reliability below 0.01 counts as no spread.
    • Shrinkage against the risk model: under compare_to="model" (and the equivalent center=1.0, overdispersion=False) the estimate columns, which were empty, now use a prior centered on the pooled value with τ̂ around it, and judge each provider against 1.0. tau= is accepted there and sets only that spread. Limits and flags are unchanged.
    • New core helpers gamma_quantile and beta_quantile (no new dependencies).
    • docs/examples/hierarchical_readmissions.ipynb: the patient-level hierarchical model in PyMC beside funnel(), with an optional hospital level. On its simulated data the two agree to a correlation of 0.996.
    • With within_dispersion the intervals cover about 90%, not 95% (methods §5).
    • Cited: Keenan 2008, Dimick 2010, Marshall & Spiegelhalter 1998, Goodwin 2013, Jones & Spiegelhalter 2011; README physician section now cites Hofer 1999 and Goodwin 2013.

    • Python only; the Excel add-in does not draw funnels.

    • color_by="fdr" on FunnelResult.plot(): colors the points by their q-value tiers (outlier q < fdr_levels[0], alert q < fdr_levels[1]) on a signal="limits" result. The signal column and the drawn 95% and 99.8% lines are unchanged; the legend and caption state the q rule. A figure can now match an action list built from q_value without recoloring traces by name.

    • fdr_watch= (e.g. 0.20) adds a pale, open-diamond watch tier for q below it, on the figure only. It has a watch role in styles=.
    • README, methods §4.11 and the provider-funnels skill now say that under signal="limits" a point beyond the 95% line can have a large q-value.
    • Python only; the Excel add-in does not draw funnels.

    1.1.0 (2026-11-01)¶

    Added¶

    • benchmark= on funnel(): a goal the best providers already reach, drawn as a dashed line, with benchmark_share= (default 0.10) defining "the best". Both need worse=; methods §4.18.
    • "abc": Kiefe and Weissman's achievable benchmark of care. Providers are ranked by (x + 1)/(n + 2), and the best are pooled until they hold 10% of patients, ties included. It reproduces GAMUT's worked example. It reports the providers who set it and their volumes, and the minimum sufficient denominator (whose exact rule reproduces Kiefe's Table 3). It also gives the ABC without providers below that denominator (Hall et al. 2013).
    • "eb": the 90th percentile of the shrunk eb_rate toward the better side (O'Brien et al. 2008), for outcome measures.
    • summary["benchmark"] is one dict: method, share, value, and under "abc" providers, coverage, group_denominator, msd, n_below_msd and without_small. The columns are benchmark, meets_benchmark, and benchmark_group under "abc".
    • Python only. The TypeScript engine and the Excel add-in do not have it yet.

    1.0.0 (2026-11-01)¶

    1.0 is a breaking release. qic() and funnel() now share one vocabulary, display options moved to .plot(), the package imports without plotly, and both functions were checked against R (qicharts2, FunnelPlotR, NHSRplotthedots). Every removed or renamed argument raises a TypeError naming its replacement, so running an app once lists the changes to make.

    Breaking: calling qic() and funnel()¶

    • Keyword-only after data. qic(data=None, *, x=None, y, n=None, chart="run", ...) and funnel(data=None, *, y, n, measure, ...). A positional qic(x, y) call raises.
    • Display options moved to .plot(): title, subtitle, caption, xlab, ylab, styles, label_signals, x_range, y_range, show_legend, width, height on both, plus x_log on funnels and part_labels, show_95, show_labels, show_grid, show_x_labels, decimals, point_size, x_format, x_angle, x_pad, x_order, y_expand, y_neg, y_percent, connect, runs_highlight, flip, nrow, ncol and scales on qic().
    • Renamed arguments:
    Old New Where
    cl= center= both
    point_labels= label= both
    hover_extra= hover= both
    test_min_expected= fdr_min_denominator= funnel()
    signal_side= worse= funnel()
    signal_method= signal= funnel()
    levels= limits= funnel()
    • Removed: print_summary, y_percent_accuracy and strip_horizontal (no effect), and the hidden chart="ip" (an i chart of a rate is chart="i", y=events, n=cases).
    • facets= takes one column or a list on both functions. The facet columns lead .data under their own names.

    Breaking: results¶

    • qic() columns. sigma_signal (bool) is now signal ("outlier" or "none"), the same column a funnel has. runs_signal now marks only the points that form a pattern (0.10's runs_signal_localized); too few crossings is summary["crossings_signal"].
    • qic() summary. run_signal is longest_run_signal, run_threshold is longest_run_max, crossings_threshold is n_crossings_min, and limit_basis is gone. New: chart, method, n_outlier, runs_signal, and per-method keys.
    • funnel() summary. phi_raw and phi_debiased are one key, phi, as the chosen tau_method defines it. test_min_expected is fdr_min_denominator. New: limit_method, tau_scale, min_detectable_median.
    • Every result has to_dict() and to_json(). FunnelResult lives in qikit.results with the others.

    Breaking: packaging and modules¶

    • plotly is optional. pip install "clinical-qikit[plot]" for .plot(). The core depends only on numpy and pandas, and import qikit does not load plotly. .plot() without plotly raises an ImportError naming the extra.
    • Modules. qikit.spc (a package) and qikit.render are gone. The numeric core is qikit.core (dist, constants, shewhart, rules, contours, dispersion, pvalues, power); the front doors are qikit.spc (a module) and qikit.funnel; figures are qikit.plot. Import from qikit itself; the internal paths are not API.

    Behavior changes¶

    Each moves results on some data. "More" or "less sensitive" is relative to 0.10.

    • tau_method="spiegelhalter" is the default again, in both engines. 0.10's debiased default was not sensitive enough for screening in production use: it found a planted outlier 38% of the time against 70% (methods §5, K = 150, τ = 0.3). The published estimator is also uncorrected like the CQC, NHS and FunnelPlotR estimators. Flag rates return to 0.9's. "winsorized" remains for when the stated chance-flag rate must hold. More sensitive.
    • Run-chart rule (anhoej) matches qicharts2: longest run > round(log₂ n) + 3, and no minimum n. 0.10 used floor(log₂ n) + 3 with ≥. Less sensitive: in simulation false signals fall from 2–10% to 0–2%, and power to see a 1 SD shift falls from 37% to 13% at n = 30. The crossings rule is unchanged. method="nhs" or "ihi" restore a shorter run under a published rule set.
    • xbar and s charts take their spread from the baseline and each part, honouring freeze=, part= and exclude=. More sensitive after a real change.
    • g chart limits come from the mean, with the median drawn as the centre line (Montgomery, qicharts2). Limits about 10–15% wider. Less sensitive.
    • Laney σ_z is screened at 3.267·MR̄ and no longer floored at 1. Narrower limits on under-dispersed series.
    • method="ihi" uses Provost and Murray's run-chart rules (shift 6, trend 5) on run charts, adds 2 of 3 beyond 2σ and 15 within 1σ on Shewhart charts, and passes over repeated values in a trend. More sensitive.
    • n= divides y on every chart, as in qicharts2. p and pp upper limits are capped at 1; the MR chart's lower limit is 0; a moving range across a part boundary is NaN.
    • Grouped x is sorted when numeric or a date, so runs and moving ranges follow time.
    • c₄ is exact (from the gamma function), not a table. A₃, B₃ and B₄ follow it. Differences are in the fourth significant figure.
    • A fixed center= counts K degrees of freedom in "winsorized"'s τ̂², not K − 1. τ̂² is smaller by about 1/K.
    • An estimated within-dispersion below 1 (binary-outcome O/E from case rows) is kept and labelled as the binomial-variance correction, not floored.

    Added¶

    • method="nhs": NHS England's Making Data Count rules on qic(), with variation and special_cause per point, summary["variation"], and summary["assurance"] against target=. Plot colours for improving, concerning and neutral special causes. Checked against NHSRplotthedots.
    • tau_method="cqc" and "shmi": CQC and NHS SHMI over-dispersion on the √, arcsine or log scale, as FunnelPlotR computes them, with limits drawn on that scale and mapped back (limit_method="transformed_normal"). Methods §4.17.
    • funnel_sensitivity(): one row per provider with its tier under each τ option and a consistent flag.
    • Reference tests against R. fixtures/reference/ holds 31 cases from qicharts2, FunnelPlotR and NHSRplotthedots, regenerated by scripts/make_reference_fixtures.R; tests/test_reference.py checks them to 1e-6, with each departure listed.
    • Validation: y < 0, y > n on proportions, center out of range, freeze, part, method, agg_fun, and facet names that collide with output columns.
    • Documentation for people and agents: docs/qic-methods.md, docs/snowflake.md, src/qikit/AGENTS.md (shipped in the wheel), llms.txt, and the skills/spc-monitoring skill. py.typed marks the package as typed.
    • tests/test_docs.py: every argument, quoted value, summary key and column named in the README, AGENTS.md, llms.txt, the skills and the methods docs is checked against the code, and the skills' column lists are checked in both directions.

    0.10.0 (2026-10-31)¶

    Behavior change¶

    • The over-dispersion estimate is debiased by default, in both engines (tau_method="winsorized"). The 10%-winsorized φ̂ is multiplied by its Gaussian consistency factor 1.4735 (Spiegelhalter 2005, eq. 9) before τ² is estimated. τ̂ is larger, the adjusted contours are wider, and fewer average providers flag. Without the factor, at 1,000 physicians (E from 2 to 60), τ̂ was 0 for a true spread of 0.10, and average providers flagged at about twice the stated rate. On the bundled example (data/examples/physician_mortality_oe.csv, three years) τ̂ goes from 0 to 0.113, and the same three physicians are outliers. tau_method="spiegelhalter" reproduces 0.9 (and FunnelPlotR/CQC) exactly. The engine core, qic() on O/E charts and the TypeScript engine (tauMethod) use the same default. The shared fixtures that check Spiegelhalter's published numbers now pin tauMethod: "spiegelhalter", and three new fixtures (funnel_*_winsorized) check the default in both engines. See docs/methods.md §4.3.

    Added (funnel())¶

    • tau_method=: "winsorized" (default), "spiegelhalter" (as published) or "ml" (maximum likelihood of the chart's own random-effects model, with a profile-likelihood tau_ci). tau=: a τ fixed in advance (a number, or one per facet). Summary keys tau_method, tau_source, tau_estimated, tau_ci; notes below 30 providers and when a fixed τ has drifted from this period's estimate (§4.16).

    • prob_worse column: the posterior probability that a provider is worse than average (the CMS question), alongside signal (unusual among peers) (§4.14, §4.16).

    • reliability, eb_rate, eb_excess, raw_excess columns: shrinkage by the exact posterior mean of the chart's own Poisson–gamma or beta-binomial model (§4.14).

    • p_value_drop1, flag_survives_drop1, fragility columns: single-case robustness (§4.15). max_case_y=/max_case_n= supply the worst case from SQL.
    • cases=/sum_sq=: within_dispersion="estimate" and the clustering check from one row per provider aggregated in SQL; equal to the stay-level result to rounding (§4.12).
    • within_dispersion="<column>": one φᵢ per provider (e.g. case-mix weighted by DRG); adds effective_denominator, the plot's x axis (§4.12).
    • test_min_expected=: a volume floor for the false discovery rate step only (independent filtering) (§4.11).
    • Summary keys phi_raw, phi_debiased, test_min_expected, n_filtered, n_fragile, and notes for fragile flags and filtering.

    Performance¶

    • dist.py walks are vectorised with strictly sequential numpy accumulations and cached per distribution. Every value is bit-identical to 0.9. A 1,000-provider oep funnel at E from 30 to 2,000 takes about 0.3 s cold, down from 1.3 s. scipy is not required. Monkeypatches of the removed qikit.spc.dist.poisson_cdf have had no effect since 0.8 and can be deleted.

    Evaluated and declined¶

    These are recorded in docs/methods.md §6 with reasons: per-provider own-variance continuous_oe, q_value_loo, Storey/power-screened FDR, winsorized/median center lines, and smoothed display contours.
