# qic(): methods and conformance

This document records how `qic()` computes center lines, limits and signals, which
published source each choice follows, and every place it departs from that source. It
is the time-series counterpart of [methods.md](methods.md), which covers funnels.

`qic()` follows R's qicharts2 [1] unless stated otherwise. `tests/test_reference.py`
compares it with qicharts2, and with NHSRplotthedots [5] for `method="nhs"`, on the
packages' own data to 1e-6. The R output lives in `fixtures/reference/` and is
regenerated by `scripts/make_reference_fixtures.R`. Each accepted difference is listed
in the test's `DEPARTURES` table and in §4 below.

## 1. The pipeline

`src/qikit/spc.py` runs these steps in order:

1. **Normalize.** Columns or sequences become one frame. `n=` divides `y` on every
   chart, as in qicharts2, so an i chart of a rate is `chart="i", y=events, n=cases`.
2. **Aggregate.** Rows that share an `x` become one subgroup: numerators and
   denominators summed, raw values combined by `agg_fun=`. Numeric and date `x` are
   sorted first, so runs and moving ranges follow time, not row order. Text `x` keeps
   its order. `x_period=` buckets dates.
3. **Baseline.** `freeze=k` sets the limits from points 1..k. `part=` splits the chart
   into phases; `part=k` and `freeze=k` both mean "ends at point k". `exclude=` drops
   points from the limits and the rules but still draws them.
4. **Limits.** `core/shewhart.py`, per part, from that part's baseline points.
5. **Rules.** `core/rules.py`, per part, by `method=`.
6. **Table.** `result.data` and `result.summary`.

## 2. Center lines and limits

σ̂ is estimated from the baseline points of each part.

| Chart | Center line | σ̂ | Source |
|---|---|---|---|
| `run` | median | none | [1] |
| `i` | mean | screened MR̄/d₂ (MR above 3.267·MR̄ dropped, then MR̄ recomputed) | [1, 2] |
| `mr` | MR̄ | UCL = D₄·MR̄ = 3.267·MR̄, LCL = 0 | [2] |
| `xbar` | grand mean, weighted by subgroup size | Sp/c₄(d + 1), pooled over baseline subgroups | [2] |
| `s` | c₄(nᵢ)·σ̂ | as `xbar` | [2] |
| `t` | i chart on y^(1/3.6), back-transformed | as `i` | [1, 3] |
| `p` | Σy/Σn | √(p̄(1 − p̄)/nᵢ); UCL capped at 1, LCL floored at 0 | [2] |
| `pp` | Σy/Σn | Laney: σ_z·√(p̄(1 − p̄)/nᵢ) | [4] |
| `c` | mean | √c̄ | [2] |
| `u` | Σy/Σn | √(ū/nᵢ) | [2] |
| `up` | Σy/Σn | Laney: σ_z·√(ū/nᵢ) | [4] |
| `g` | median, drawn as CL | limits from the mean ḡ: ḡ ± 3√(ḡ(ḡ + 1)), LCL floored at 0 | [1, 2 p. 319] |

**c₄ is exact,** √(2/(n − 1))·Γ(n/2)/Γ((n − 1)/2), not a table. A₃, B₃ and B₄ are derived
from it. The TypeScript engine computes the same function.

**Laney's σ_z** is the screened MR̄ of the standardized values zᵢ divided by 1.128,
with no floor at 1, as in qicharts2. Under-dispersed data therefore draw limits
narrower than the p or u chart. A series with every z equal has σ_z = 0 and NaN limits.

**The 2σ lines** (`ucl_95`, `lcl_95`) are CL ± 2σ̂ on every chart, capped like the 3σ
lines. They are what the 2-of-3 rules read.

**`method="nhs"` on an i chart** uses Making Data Count's 2.66·MR̄ for the 3σ half-width,
with the same screened MR̄ [5]. 3/d₂ = 2.6596, so the difference is in the fourth
significant figure.

## 3. Rules (`method=`)

A point beyond the 3σ limits is the chart's own test: `signal = "outlier"`. The rules
find patterns and mark the points that form them in `runs_signal`.

### 3.1 `"anhoej"` (default)

Anhøj and Olesen's rules [6], as qicharts2 implements them. Points on the center line
are not useful and are skipped.

- **Longest run.** A signal when the longest run on one side is longer than
  round(log₂ n) + 3, where n is the number of useful points.
- **Crossings.** A signal when the number of crossings is fewer than the 5th percentile
  of Binomial(n − 1, ½), `qbinom(0.05, n − 1, 0.5)`.
- **No minimum n.** qicharts2 applies both rules at any n.

`summary` reports `n_useful`, `longest_run`, `longest_run_max`, `n_crossings`,
`n_crossings_min`, `longest_run_signal` and `crossings_signal`. Too few crossings is a
property of the whole series, so the plot can color every point (`runs_highlight=`).

**Sensitivity.** Before 1.0 qikit used floor(log₂ n) + 3 with "at least", which flags
runs one or two points shorter. Simulated with the median from the same data, false
signals from the run rule fall from 2–10% to 0–2% across n = 12 to 48. Power to see a
1 SD shift in the last half falls from 18% to 8% at n = 20 and from 45% to 19% at
n = 48. The crossings rule still catches most sustained shifts. `"nhs"` or `"ihi"`
recover the shorter run under a published rule set.

### 3.2 `"nhs"`: Making Data Count

NHS England's rules for XmR charts [5, 7], as NHSRplotthedots implements them:

| Rule | Condition |
|---|---|
| Beyond limits | a point outside the 3σ limits |
| 7-point trend | 7 points in a row strictly rising or falling; a repeated value breaks it |
| 2 of 3 near a limit | 2 of 3 consecutive points beyond 2σ, all three on the same side |
| 7 on one side | 7 points in a row on one side of the mean; a point on the mean breaks it |

Each point takes the first of these it belongs to, in the order of the table, as its
`special_cause`. A point inside a trend takes the trend's direction; at the join of two
trends, the one it starts.

With `worse=`, each point's `variation` is `"improving"`, `"concerning"` or `"common"`.
Without it, a special cause is `"neutral"`. `summary["variation"]` is the last point's,
which is what the Making Data Count icon shows.

With `target=` and `worse=`, `summary["assurance"]` is judged at the last point's
limits. It is `"pass"` when the target lies beyond the limit on the bad side, so the
process cannot miss it by chance. It is `"fail"` when the target lies beyond the limit
on the good side, and `"variable"` when it lies inside the limits.

### 3.3 `"ihi"`: Provost and Murray

From *The Health Care Data Guide* [3]. Repeated values are passed over in a trend.

- **Run chart:** a shift of 6 or more on one side of the median, and a trend of 5 or
  more.
- **Shewhart chart:** a shift of 8, a trend of 6, 2 of 3 beyond 2σ on one side, and 15
  in a row within 1σ.

The run chart's runs-count table is not implemented. Anhøj's crossings rule, the
default method, answers the same question with a formula rather than a table.

### 3.4 `"weco"` and `"nelson"`

The Western Electric zone rules [8] and Nelson's eight tests [9], less the point beyond
3σ, which is `signal`. Both need limits, so they do not apply to a run chart.

### 3.5 Short series: `provisional` and the notes

A chart of a few points cannot show that a process is stable, so qikit says so in words.
It never changes `signal`, `runs_signal` or the limits.

| Baseline points | Charts | What qikit does |
|---|---|---|
| fewer than 12 | all | `summary["provisional"]` is True, a note says the series is too short to judge, and `print(result)` reads "No signal so far" in place of "looks stable" |
| 12 to 19 | those with control limits (not `"run"`) | a note calls the limits provisional; `provisional` stays False |
| 20 or more | all | nothing |

The count is of the points that set the current center line: the baseline points of the
last part. `freeze=10` therefore leaves a chart provisional however many points follow,
and so does a new part (`part=`) that is still short.

**Where the numbers come from.** They are rules of thumb, set as the constants
`MIN_POINTS` and `MIN_LIMIT_POINTS` in `spc.py`, and published guidance does not agree
on one figure:

- **20** is the usual figure for control limits from a stable baseline (Provost and
  Murray [3]; Montgomery [2] asks for 20 to 25 subgroups).
- **12 is qikit's own choice.** It lies between the roughly 10 points at which run-chart
  guidance sets a baseline median (Perla, Provost and Murray [10]) and the 15 that
  Making Data Count [7] asks for before drawing process limits. A team reporting under
  Making Data Count should read 12 to 14 points as too few for limits, which the
  12-to-19 note already says.

The run rules give the practical reason for caution (§3.1): at n = 20 they have 8% power
to see a 1 SD shift in the last half of the series, so no signal on a short series says
little.

## 4. Departures from qicharts2

Each is deliberate and listed in `tests/test_reference.py`.

- **The MR chart's 2σ line.** qikit draws MR̄(1 + 2·d₃/d₂) = 2.511·MR̄, the moving
  range's own 2σ. qicharts2 draws two-thirds of the UCL, 2.178·MR̄. Only `ucl_95` is
  affected.
- **xbar with unequal subgroups.** qikit uses ±3σ̂/√nᵢ with the unbiased
  σ̂ = Sp/c₄(d + 1), d the pooled degrees of freedom. qicharts2 uses A₃(nᵢ)·Sp, which
  corrects with c₄(nᵢ). The two differ by a fraction of a percent.
- **s with unequal subgroups.** qikit's center line is c₄(nᵢ)·σ̂, the expected sᵢ, so it
  moves with nᵢ. qicharts2 draws a flat CL = Sp with B₃/B₄(nᵢ) limits. With equal
  subgroups the two agree.
- **A moving range across a part boundary** is NaN in qikit, so one part's spread never
  leaks into the next. qicharts2 computes each part separately and agrees.

## 5. What changed in 1.0

Each change below moves results on some data. The CHANGELOG has the full list.

| Change | Effect on signals |
|---|---|
| Run rule: round(log₂ n) + 3 with "longer than" | Fewer false signals, less power (§3.1) |
| xbar/s spread from the baseline and each part | More sensitive after a real change |
| g chart limits from the mean | Limits about 10–15% wider |
| Laney σ_z: screened, no floor | Narrower limits on under-dispersed series |
| `ihi` run-chart rules 6/5; zone rules on Shewhart charts | More sensitive, as published |
| `n=` divides y on every chart; p UCL capped at 1; MR LCL 0 | None on valid data |
