    API reference¶

    These pages are the docstrings, the same text help() shows. Each function opens with a table of which settings fit which data.

    Over time¶

    qic ¶

    qic(data=None, *, x=None, y, n=None, chart='run', method='anhoej', freeze=None, part=None, exclude=None, center=None, target=None, worse=None, agg_fun='mean', x_period=None, multiply=1.0, facets=None, label=None, hover=None, notes=None, **removed)

    A statistical process control chart: one measure over time, judged against its own past. Returns an SPCResult; result.data is the table, result.plot() the figure.

    Choosing the chart¶
    You have, per period chart= y=, n=
    any measure, few assumptions (start here) "run" y
    one continuous value (LOS, wait time, O/E) "i" y
    events out of cases (H&P in 24 h, mortality) "p" y=events, n=cases
    the same, n in the thousands (over-dispersed) "pp" y=events, n=cases (Laney)
    events over exposure (infections/line-days) "u" y=events, n=exposure
    the same, exposure in the thousands "up" y=events, n=exposure (Laney)
    an O/E ratio over time "u" y=observed, n=expected
    counts with constant opportunity "c" y=count
    several raw values per period (subgroups) "xbar" y=raw values, x=period
    and their spread "s" y=raw values, x=period
    cases between rare events (never events) "g" y=cases between
    days between rare events "t" y=days between
    the moving range of an i chart "mr" y

    With data=, x=, y=, n= name columns, and rows sharing an x are aggregated into one subgroup: events and denominators summed, raw values averaged (agg_fun=). x is sorted when it is a number or a date (a datetime column, or Python date objects as Snowpark returns them); text x keeps its order, so parse text dates first. Without data=, they are sequences, one value per point. A missing y (None, NaN, blank) is a gap in the chart; text that is not a number is an error.

    Choosing the rules (method=)¶
    • "anhoej" (default): qicharts2's run rules, an unusually long run on one side of the center line or unusually few crossings of it (Anhøj & Olesen 2014).
    • "nhs": NHS England's Making Data Count, for XmR (chart="i") boards: 7 on one side, 7 rising or falling, 2 of 3 near a limit. Pass worse= to class each special cause as improving or concerning, and target= for the assurance verdict.
    • "ihi": Provost & Murray's rules (shift, trend, and on Shewhart charts the zone rules). "weco", "nelson": the classic zone rules.
    Reading the result¶

    result.data, one row per point in plotted order:

    • x, label, y (after multiply=), n (when given; the subgroup size on xbar/s).
    • cl, ucl, lcl: center line and 3σ limits; ucl_95, lcl_95: the 2σ lines.
    • signal: "outlier" beyond ucl/lcl, else "none".
    • runs_signal: the point is part of a pattern the rules found (a long run, a trend). Too few crossings is a property of the whole series: summary["crossings_signal"].
    • variation (method="nhs"): "improving", "concerning", "neutral" (no worse=) or "common", Making Data Count's reading of each point; special_cause: the rule that made it so ("" for common cause).
    • part, baseline (used to set the limits), excluded, target, notes, hover columns, and one column per facets= column.

    result.summary: signals (any outlier or pattern), n_outlier, runs_signal, the rule method's own keys (anhoej: n_useful, longest_run, longest_run_max, n_crossings, n_crossings_min, longest_run_signal, crossings_signal; others: rules_fired), sigma_z (pp/up), parts (one dict per part; the top level describes the last part, the current process), variation and assurance (method="nhs"), by_facet, and: notes, sentences to show a reader (too few points, trial limits, gaps, a frozen baseline; prefixed by facet when faceted), and provisional, True when fewer than 12 points set the center line, so "no signal" is not yet "stable".

    Parameters¶
    • data: a DataFrame, or None to pass sequences.
    • x, y, n: columns of data (or sequences). n= is required on p/pp/u/up; on any other chart it divides y, as in qicharts2 (an i chart of a rate).
    • chart, method: see above.
    • freeze: the baseline ends at this point (1-based): the limits come from points 1..freeze and later points are judged against them.
    • part: split the chart into parts, each with its own center line, limits and rules: the point(s) where each part ends (1-based, as freeze=), or a column whose value changes between parts (e.g. "before"/"after").
    • exclude: points to leave out of the limits and the rules (drawn faded): a column of booleans, or 1-based positions.
    • center: a fixed center line instead of the baseline's.
    • target: a target line: a number, or a column.
    • worse: "higher" or "lower": which direction is bad, for method="nhs" (improving or concerning special cause; assurance against target=).
    • agg_fun: how raw values in one subgroup combine when there is no n=: "mean", "median" or "sum".
    • x_period: aggregate a date x into periods: "day", "week", "month", "quarter", "year" (or a pandas frequency).
    • multiply: scale y and the limits, e.g. 1000 for a rate per 1,000.
    • facets: one column, or a list of columns: one chart per value (or combination). result.data keeps those columns, so it is ready to write back to a table.
    • label: display name per point (a column or sequence); hover : extra tooltip columns; notes : annotations per point (a column or sequence).

    Display options (title, axis labels, styles, ...) are arguments of result.plot(). result.to_table() is .data with every possible column in a fixed order (see qikit.schema("qic")), for a database table; result.brief() is the verdict, the notes and only the flagged points, small enough to read at a glance.

    SPCResult dataclass ¶

    What qic() returns. data: one row per point (qic's docstring lists every column); summary: what the rules found and how the limits were set. plot(**options) draws it.

    signals property ¶

    signals

    Whether any point is an outlier or any rule found a pattern.

    plot ¶

    plot(**options)

    A Plotly figure. Options: title, subtitle, caption, xlab, ylab, show_95, show_labels, show_grid, show_x_labels, label_signals ("outlier"), runs_highlight ("localized", "all", "none"), styles (restyle by role), x_range, y_range, x_order, x_format, x_angle, y_percent, y_neg, y_expand, decimals, point_size, connect, show_legend, flip, width, height, and nrow, ncol, scales for facets. An unknown name raises TypeError.

    to_table ¶

    to_table()

    .data with every column of qikit.schema("qic"), in that order and with those types, empty where this call did not produce it: the facets= columns, the schema columns, then the hover= columns. The same shape for every call with the same facets= and hover=, as a table or a Snowpark RETURNS TABLE clause needs.

    brief ¶

    brief(digits=4, limit=25)

    What was found, small enough to read or to hand to a language model: the verdict, the notes, and only the flagged points (an outlier, or part of a run), the most recent limit of them, with numbers at digits significant figures. JSON-safe. Faceted, "facets" gives each chart's verdict.

    Across providers¶

    funnel ¶

    funnel(data=None, *, y, n=None, measure, unit=None, label=None, hover=None, facets=None, exclude=None, center=None, overdispersion=None, compare_to=None, within_dispersion=None, tau_method=DEFAULT_TAU_METHOD, tau=None, cases=None, sum_sq=None, max_case_y=None, max_case_n=None, fdr_min_denominator=None, worse=None, signal='limits', limits=DEFAULT_LEVELS, fdr_levels=DEFAULT_FDR_LEVELS, benchmark=None, benchmark_share=0.1, multiply=1.0, interval=0.95, **removed)

    Compare providers on one measure with a funnel plot, and flag the unusual ones. Returns a FunnelResult; result.data is the table, result.plot() the figure.

    Two questions, both legitimate (methods §2), named by compare_to=: "peers" (the default) asks "is this provider unusual among its peers?", judging each provider against the pooled value and the measured spread between providers as well as chance; "model" asks "does this provider differ from the risk model?" (center=1.0, overdispersion=False). Decide which before looking. A fixed center= with overdispersion=True answers neither: any system-wide gap between the providers and that center is absorbed into tau, widening every limit, and a warning says so (methods §4.2.1).

    Reading the result¶

    result.data has one row per provider (per unit and facet), in plotted order (by denominator):

    • signal: "outlier", "alert" or "none". The tiers never overlap; an outlier is not also an alert. Under worse= only the worse side is flagged.
    • direction: "higher" or "lower", which side of the center line the point is on.
    • y: the plotted value (O/E ratio, proportion, rate or mean, after multiply=); numerator and denominator: the summed y= and n= inputs, in the caller's units.
    • effective_denominator: only with a per-provider within_dispersion column: the denominator ÷ φᵢ the model sees, which is the x axis of the plot.
    • cl: the center line. lower_outlier / upper_outlier: the outer contour (99.8% by default); lower_alert / upper_alert: the inner one (95%). Each contour is the boundary of the test, so a point is beyond the upper_outlier line exactly when its one-sided p-value is below 0.001.
    • p_value: against the same model the contours are drawn from (one-sided toward worse=, or doubled for two-sided); q_value: its Benjamini–Hochberg adjustment across the providers in this chart (each facet separately; excluded providers are not tested).
    • min_detectable: the smallest true value this provider could have flagged with 80% power. A provider inside the funnel at physician volumes is often "not enough data", not "fine". ci_lower / ci_upper: an exact 95% interval for the provider's own value.
    • excluded: dropped from the center line, the dispersion estimates and testing.
    • raw_excess: (numerator − cl·denominator), signed so positive is worse: the excess days or events. Shrunk estimates (methods §4.14). Each provider's true value has an exact posterior: gamma for counts (O/E, rate, mean), beta for proportions, on effective counts. Its prior is centered on the center line (under compare_to="model", the pooled value) with the spread estimated by maximum likelihood (or tau=), whatever tau_method the limits use. The columns:
    • reliability: the shrinkage weight, 0 to 1: how much of the provider's difference is signal rather than chance. 0 for every provider when there is no measurable spread, and on an unadjusted chart with a custom center. 0.7 is the usual floor for high-stakes use of a single score (Adams et al. 2010).
    • eb_rate, eb_excess: the shrunk (empirical Bayes) value, the posterior mean, and its excess over the reference. Sort on eb_excess to prioritize.
    • eb_low, eb_high: an equal-tailed interval= (95%) interval for the provider's true value from the same posterior, on the plotted scale. NaN when there is no measurable spread (a note says so). With within_dispersion it runs about 5 points short of nominal (methods §5).
    • prob_worse: the posterior probability that the provider's true value is worse than the reference ("is this provider truly worse?", the CMS question), where signal answers "is it unusual?" (methods §4.16). NaN when there is no spread.
    • estimate_flag: where [eb_low, eb_high] lies against the reference: "worse" or "better" with worse= ("higher" or "lower" without it) when wholly on one side, else "no different"; None with no interval. It answers a different question from signal and has no multiplicity control: about 5% of average providers' intervals miss their true value. The reference is summary["reference"]: the center line, or 1.0 under compare_to="model".
    • p_value_drop1, flag_survives_drop1, fragility: single-case robustness (case-level rows, or max_case_y=/max_case_n= from SQL). Descriptive, never a test (§4.15).
    • benchmark, meets_benchmark: with benchmark=, the goal (the same value on every row of a facet) and whether the provider's own value is at it or better. benchmark_group (benchmark="abc"): the best performers the ABC pools. A goal, not a test: signal is unchanged (methods §4.18).
    • one column per facets= column, and the hover= columns.

    result.summary: n_providers, n_tested, n_outlier, n_alert, expected_false_flags (per tier: the chance count under signal="limits", the false discovery bound under "fdr"), center, tau (the spread of true values between providers; on the transformed scale under "cqc"/"shmi", see tau_scale), phi, tau_method, tau_source, tau_estimated, tau_ci ("ml"), compare_to, center_gap, center_gap_p and tau_pooled (the fixed-center gap check, methods §4.2.1; None unless center= is fixed with overdispersion=True and tau estimated), reference (what the estimate columns are judged against), estimate_tau (the spread of their prior) and estimate_tau_ci (its 95% interval, None when tau= is given), count_model, limit_method, p_value_method, within_dispersion and its source, dispersion_shape, underpowered, n_underpowered, min_detectable_median, n_filtered, n_fragile, n_rows_dropped (rows missing y, n or unit, left out of the sums), notes (sentences to show readers), and with benchmark=, benchmark: a dict of method, share and value, and under "abc" also providers, coverage (their share of the denominator), group_denominator (median, min, max), msd (minimum sufficient denominator), n_below_msd and without_small. Under measure="mean", case_sd: the spread of a single case, √(φ·center), in y's units. Faceted: the counts summed, notes prefixed, and each facet's summary in by_facet. print(result) summarizes it in words.

    Parameters¶
    • data: DataFrame of providers, or of cases (stay- or survey-level rows) to be summed per unit. Without data=, y, n, unit, label are sequences and hover a dict. A row missing y, n or unit is left out of the sums and counted in summary["n_rows_dropped"], never read as zero; a provider with no complete row is listed with no value and not tested. Text that is not a number is an error.
    • y, n: columns (or sequences): the numerator and denominator. Under measure="mean", y is the amount and n the case count: 1 per row (the default when n is omitted) or each provider's COUNT(*) alongside sum_sq=.
    • measure: "oe" (observed / expected: risk-adjusted mortality, readmission, length of stay), "proportion" (events / cases), "rate" (events / exposure) or "mean" (a per-case amount ≥ 0 such as minutes or cost, averaged per provider; the quasi-Poisson model with φ estimated, in y's own units, methods §4.19).
    • unit: provider identifier column; rows are providers when omitted.
    • label: display name column (the first value per unit); hover : extra tooltip columns.
    • facets: a column, or list of columns: one funnel per value, each with its own center line, dispersion and Benjamini–Hochberg step.
    • exclude: a boolean column, or a unit id or list of unit ids, left out of the center line, dispersion and testing (still drawn, faded).
    • center: a fixed center line (a target). Pair it with overdispersion=False: with the spread allowance on, a gap between the providers' pooled value and the center widens every limit, and a UserWarning says so (methods §4.2.1). For O/E against the risk model use compare_to="model".
    • overdispersion: judge each provider against the estimated spread between providers (Spiegelhalter's additive τ²) as well as chance. Default True (unless compare_to="model").
    • interval: coverage of eb_low / eb_high, 0.95 by default.
    • compare_to: which question the chart answers. "peers": the pooled center line and overdispersion=True (the default settings). "model": O/E against the risk model's expected, center=1.0 and overdispersion=False; measure="oe" only. A center= or overdispersion= that contradicts it is an error. None (default): center= and overdispersion= as given. Recorded in summary["compare_to"] ("peers", "model" or "custom"). Under "model" the limits and signal use 1.0 with no spread, but the shrunk estimates use a prior centered on the pooled value (methods §4.14), and tau= sets only their spread.
    • within_dispersion: how much more variable each count is than its model because units clump inside cases (patient-days; the items of one survey). 1.0 (default) means independent units; under measure="mean" the default, and the only scalar, is "estimate" (a column of φᵢ is also accepted). "estimate" computes it from case-level rows; a number supplies it (e.g. from SQL: SUM(POWER(los - exp, 2) / exp) / (COUNT(*) - COUNT( DISTINCT provider))); a column name gives one φᵢ per provider (case-mix weighted, methods §4.12). The model then sees y/φ out of n/φ. An estimate below 1 (binary outcomes, whose variance Σp(1 − p) is below E) is kept and noted.
    • tau_method: how τ is estimated (methods §4.16, §4.17). "spiegelhalter" (default): Spiegelhalter's 10%-winsorized moment estimator as published, as CQC, NHS and FunnelPlotR use it on the natural scale. "winsorized": the same with its Gaussian consistency factor (eq. 9), calibrated to the stated false-flag rate at large K but less sensitive. "ml": maximum likelihood of the chart's own model, with tau_ci; not robust to outliers. "cqc", "shmi": FunnelPlotR's square-root (arcsine for proportions) winsorized and log truncated methods, drawn as normal contours on that scale, to reproduce CQC and NHS SHMI funnels.
    • tau: a τ fixed in advance instead of estimated (a number, or a dict per facet). This period's estimate is still reported as tau_estimated.
    • cases, sum_sq: per-provider SQL totals (k, and Σ y²/n over the provider's cases) so within_dispersion="estimate" needs no case rows. Pass both or neither. Under measure="mean" n is the case count, so pass sum_sq= = SUM(y * y) alone.
    • max_case_y, max_case_n: per-provider SQL worst case toward worse= (MAX_BY), for p_value_drop1 and flag_survives_drop1. Under measure="mean" max_case_y alone (max_case_n is 1).
    • fdr_min_denominator: a volume floor for the false discovery rate step only, on the denominator the model sees (expected events, cases or exposure, ÷ φ; under measure="mean", the case count). Providers below it keep their p_value but get no q_value (independent filtering, §4.11).
    • worse: "higher" or "lower" when only one direction is bad: flags only that side and makes p-values one-sided.
    • signal: "limits" (default): outlier beyond the outer contour, alert beyond the inner one, so the flags match the drawn lines. "fdr": outlier when q < fdr_levels[0], alert when q < fdr_levels[1]. Under "limits" a point beyond the 95% line can still have a large q_value; .plot(color_by="fdr") draws the q tiers without changing the signal column.
    • limits: (outer, inner) contour coverage, default (0.998, 0.95).
    • fdr_levels: (outlier, alert) false discovery rates for signal="fdr".
    • benchmark: a goal drawn beside the funnel; needs worse= (methods §4.18). "abc": Kiefe and Weissman's achievable benchmark of care. Providers are ranked best first by (x + 1)/(n + 2), taken until they hold benchmark_share of the denominator (ties at that point included), and their raw counts pooled. Designed for process proportions; on "oe", "rate" and "mean" the ranking adds one event at the center line instead, an extension its authors would caution against (a note says so). "eb": the (1 − benchmark_share) quantile of the shrunk eb_rate across providers, toward the better side (O'Brien et al. 2008): the 90th percentile by default. The choice for "oe", "rate" and "mean" (O/E mortality, LOS, minutes or cost per case); equals the center line when the funnel finds no spread.
    • benchmark_share: the share defining "best", 0.10 by default. Choose it before looking at who the best providers are.
    • multiply: scale the plotted y, e.g. 1000 for a rate per 1,000.

    Display options (title, axis labels, styles, x_log, ...) are arguments of result.plot(); result.plot(kind="caterpillar") draws the shrunk estimates with their intervals instead; result.limits() gives the contours at any denominators. result.to_table() is .data with every possible column in a fixed order (see qikit.schema("funnel")), for a database table; result.brief() is the counts, the notes and only the flagged providers; result.facet_summary() is one summary row per facet.

    FunnelResult dataclass ¶

    What funnel() returns. data: one row per provider (funnel's docstring lists every column); summary: the model, tier counts, expected_false_flags and notes. plot(**options) draws it; limits(n=None) gives the contours at any denominators; min_denominator(reliability=0.7) gives the minimum denominator (minimum volume) at which a provider's score is reliable, and how many providers are above and below it; print(result) describes it in a few sentences.

    plot ¶

    plot(kind='funnel', **options)

    A Plotly figure against each provider's volume. Options: title, subtitle, caption, xlab, ylab, label_signals ("outlier", "alert", "both"), styles (restyle by role), x_log, x_range, y_range, show_legend, show_x_labels, width, height, and nrow, ncol, scales for facets. An unset caption states the flag rule.

    color_by="fdr" colors the points by their q-value tiers (fdr_levels) on a signal="limits" result, leaving its signal column and the drawn limits as they are; fdr_watch=0.20 adds a pale watch tier for q below it.

    kind="caterpillar" draws the shrunk estimates instead: one row per provider sorted by eb_rate, the eb_low–eb_high interval as a bar colored by estimate_flag, the raw value as a faint open circle, and the reference as a dotted line. Its options: title, subtitle, caption, xlab, ylab, top= and bottom= (keep the N highest and lowest per panel), label_flagged (None names every row up to 60 per panel and only flagged ones beyond; False names all), show_legend, width, height, styles (roles worse, better, higher, lower, no_different, raw, reference).

    to_table ¶

    to_table()

    .data with every column of qikit.schema("funnel"), in that order and with those types, empty where this call did not produce it: the facets= columns, the schema columns, then the hover= columns. The same shape for every call with the same facets= and hover=, as a table or a Snowpark RETURNS TABLE clause needs.

    brief ¶

    brief(digits=4, limit=25)

    What was found, small enough to read or to hand to a language model: the question asked, the counts, the notes, and only the flagged providers (outliers first, then by p-value; at most limit), with numbers at digits significant figures. JSON-safe. Faceted, "facets" gives each chart's counts and model.

    limits ¶

    limits(n=None)

    The contours at any denominators: columns denominator, cl, lower_outlier, upper_outlier, lower_alert, upper_alert (on the plotted y scale), plus the facet columns. n=None gives the grid the plot draws, which passes through every provider's own limits. Under a within_dispersion column the denominator is the effective one, the plot's x axis.

    min_denominator ¶

    min_denominator(reliability=0.7)

    The minimum denominator for this measure: the volume (minimum sample size, case minimum, small-numbers threshold) at which a provider's score reaches a reliability target, and how many providers are above and below it.

    Reliability is the share of a provider's difference from the center that is real rather than chance, the reliability column (methods §4.14). It rises with the denominator as n/(n + k), so each target has one floor: a provider is at or above the floor exactly when its reliability is at or above the target.

    • reliability: the target, or several, each between 0 and 1. It is a judgment about the use, not a statistical result, so ask whoever owns the decision: 0.7 is the usual floor for high-stakes profiling (public reporting, pay, credentialing; Adams et al. 2010), 0.9 for decisions about one provider, 0.5 for internal screening that is reviewed before anyone acts.

    Returns one row per target (per facet under facets=), the facet columns first:

    • reliability: the target.
    • min_denominator: the floor, in the units of n= (denominator_unit says which: expected events for O/E, cases for proportions and means, exposure for rates). Round it up. Empty when no floor exists; note says why.
    • min_low, min_high: its range from the 95% interval for the spread between providers. min_high is inf when the data cannot rule out no spread. Empty when tau= was given.
    • n_providers, n_above, n_below: providers compared, how many are at or above the floor, and how many are below it. share_above is n_above / n_providers.
    • volume_above, volume_below, share_volume_above: the denominator they hold.
    • center, tau: the model the floor comes from: the center of the estimates' prior and the spread between providers around it (summary["estimate_tau"]).
    • note: the row as one sentence to show a reader.

    .attrs["notes"] lists cautions for the whole table: few providers (the floor is imprecise, show the range), or no measurable spread (no volume makes a score reliable; compare within a larger peer group, pass tau= from earlier periods, or report at a higher level: funnel_rollup() compares levels).

    Under a within_dispersion column the floor is in effective denominators (denominator / phi), the plot's x axis. Excluded providers are not counted. Which providers are below the floor: result.data["reliability"] < target.

    funnel_sensitivity ¶

    funnel_sensitivity(data=None, *, tau_methods=('spiegelhalter', 'winsorized', 'ml'), unadjusted=True, **kwargs)

    Does a provider's flag depend on how the spread between providers was modeled?

    Runs funnel(data, **kwargs) once per tau_method (and once with overdispersion=False when unadjusted=True) and returns one row per provider: unit, label (if given), y, denominator, the facet columns, one signal_ column per run, and consistent, True when every run gives the same tier. A provider flagged under one model and not another is a judgment call to make explicitly, not a finding (methods §4.16).

    funnel_rollup ¶

    funnel_rollup(data=None, *, units=None, reliability=0.7, **kwargs)

    At which level of a hierarchy can this measure be reported reliably?

    Runs funnel(data, unit=, **kwargs) once per column in units (for example ["physician", "group", "department", "hospital"], finest first) and returns each level's result.min_denominator(reliability) rows under a leading level column: the minimum denominator at that level, its range, and how many units are above and below it (n_above, n_below) with the volume they hold. Read down the table for the finest level at which enough units, and enough of the volume, clear the floor; units below it are the ones to roll up.

    Each level is its own fit, because the spread between groups is not the spread between physicians: a coarser level has more volume per unit but usually less spread, so its floor is often higher. A level where the data show no spread has no floor at all (note says so), however large its units.

    data must have one row per case, or per unit of the finest level or finer; funnel() sums the rows within each unit. For days, means and surveys pass case-level rows, as for funnel(). reliability is one target or several (see FunnelResult.min_denominator). label= and hover= are left out: they describe one level. .attrs["notes"] holds every level's cautions, prefixed with the level.

    bchart ¶

    bchart(x, target=None, baseline=None, or_ratio=2.0, limit=3.5, data=None)

    Bernoulli CUSUM for case-by-case binary outcomes (Neuburger et al. 2017; qicharts2's bchart): one cumulative sum looking for the odds of failure rising by or_ratio, another for it falling by the same factor, each signalling at limit.

    • x: 0/1 outcomes in time order (1 = the event, e.g. a complication): a sequence, or with data= a column name. A missing outcome leaves both sums where they were.
    • target: the expected event probability p0. Or baseline=k: p0 is the event rate of the first k cases. With neither, p0 is the rate over all cases.

    Returns columns x (case number), y, cusum_up, cusum_down, signal_up, signal_down, limit; summary target, or_ratio, limit, signal_up, signal_down.

    What bchart() returns: the two Bernoulli CUSUMs and where they signalled.
